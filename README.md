# Lexio

Минималистичный тренажёр английского: интервальное повторение словаря, три режима
отбора слов в пулле (с настройкой направления и формата ответа) и задания от OpenAI
с проверкой ответов и разбором ошибок.

Словарь не написан вручную — он один раз импортируется из открытых наборов данных
(частотность, уровни CEFR, переводы из Викисловаря) и дальше живёт в вашей базе.
Прогресс по каждому слову привязан к аккаунту пользователя.

## Быстрый старт

Нужен Node.js 20.11 или новее.

```bash
git clone <репозиторий> && cd english
cp .env.example backend/.env      # затем откройте и поставьте свой JWT_SECRET
npm run setup                     # установка зависимостей + импорт словаря (~9 000 слов)
npm run dev                       # backend :4000, frontend :5173
```

Откройте http://localhost:5173 и зарегистрируйтесь. При регистрации указывается уровень
CEFR — от него зависит отбор слов и сложность заданий ИИ; поменять его можно в профиле.

Задания ИИ и диалог с репетитором требуют ключа OpenAI в `backend/.env`
(`OPENAI_API_KEY`). Без ключа всё остальное работает полностью, а разделы ИИ
показывают, чего не хватает.

## Как это устроено

Монорепо на npm workspaces: `backend` и `frontend` — независимые пакеты со своими
зависимостями и сборкой.

```
backend/            Fastify 5 + Prisma 7 + SQLite + OpenAI
  prisma/schema.prisma
  src/routes/       auth, practice, words, stats, rewards, ai
  src/services/     practice, progress, ai, enrich
  src/lib/          srs, economy, achievements, text, levels, sources
  src/tools/        import-dictionary.ts — импорт открытых словарей
frontend/           Vite 8 + React 19 + Tailwind 4
  src/pages/        обзор, тренажёр, задания ИИ, диалог, словарь, статистика, награды, профиль
  src/components/   дизайн-система и графики на SVG
  src/lib/          api-клиент, форматирование, озвучка
```

### Тренировка слов

Основа — пулл: 10–40 слов, которые задаются по одному. Верный ответ убирает слово из
пулла, неверный оставляет его до следующего круга, поэтому пулл закрывается только
когда все слова угаданы. Отбор слов учитывает частотность, уровень и приоритет
повторения, а не случайность.

Режимы отбора слов: **новые слова**, **слабые слова** (с ошибками) и **повторение**
(по сроку SRS). Для любого режима отдельно задаются направление (EN→RU или RU→EN)
и формат ответа — ввод вручную или выбор из четырёх вариантов (с платной подсказкой,
убирающей два неверных). Режим «на слух» временно скрыт. Часть режимов открывается
с ростом уровня.

Ответы сравниваются нормализованно: регистр, ё/е, лишние пробелы и знаки не влияют,
принимается любой из переводов слова. Опечатка в одну букву по расстоянию Левенштейна
считается верным ответом со сниженной наградой — это отключается в профиле.

### Память и статистика

Каждое слово пользователя ведётся по SM-2: коэффициент лёгкости, интервал, число
повторений, срок следующего показа и статус (новое → изучается → на повторении →
освоено, либо проблемное). Пишутся все попытки: что ответили, за какое время, с каким
типом совпадения, в каком режиме и в какой час — из этого собирается статистика по
уровням, темам, режимам, времени суток и дням.

### Рейтинг, уровни, серии

За занятия начисляются очки рейтинга — одна величина, которая в основном только растёт
и задаёт уровень (1–1000). Бонусы идут за первый верный ответ на слово, скорость, серию
внутри пулла и сложность режима; подсказки и опечатки уменьшают награду за конкретное
слово. Часть очков можно потратить на подсказку в формате «4 варианта» (убрать два
неверных). Рост уровня открывает режимы, оформления интерфейса и выдаёт заморозки серии.
Дневная цель и серия дней считаются по часовому поясу пользователя; пропущенный день
можно закрыть заморозкой из запаса.
### Задания ИИ

Через structured outputs OpenAI генерируются задания: перевод предложения в обе стороны,
грамматический тест, слово в пропуск, диктант на слух, письменная работа и разбор слова.
В формулировки подмешиваются слова, на которых вы чаще ошибаетесь, а ошибка в задании
двигает эти слова в начало очереди повторения. Тесты с вариантами и пропущенное слово
проверяются локально без обращения к модели; свободные ответы оценивает модель и
возвращает балл, список ошибок с исправлениями и улучшенный вариант.

Диалог с репетитором идёт по сценариям (кафе, аэропорт, собеседование и другие): каждая
ваша реплика получает ответ на английском и разбор ошибок, если они были.

## Источники словаря

Импорт выполняется скриптом `npm run db:import` (входит в `npm run setup`). Файлы
скачиваются один раз и кешируются в `backend/.cache`, дальше приложение работает только
из своей базы.

| Данные | Источник | Лицензия |
| --- | --- | --- |
| Частотность слов | [google-10000-english](https://github.com/first20hours/google-10000-english) | Public Domain |
| Уровни A1–B2, темы, части речи | [CEFR-J Vocabulary Profile 1.5](https://github.com/openlanguageprofiles/olp-en-cefrj) | CEFR-J project |
| Уровни C1–C2 | [Octanove Vocabulary Profile C1/C2 1.0](https://github.com/openlanguageprofiles/olp-en-cefrj) | Octanove Labs |
| Грамматические темы для заданий ИИ | [CEFR-J Grammar Profile](https://github.com/openlanguageprofiles/olp-en-cefrj) | CEFR-J project |
| Переводы, значения, толкования | [WikDict en-ru](https://www.wikdict.com/) | CC BY-SA 3.0, данные Викисловаря |
| Примеры употребления с переводом | [Tatoeba en-ru](https://tatoeba.org/), выгрузка [OPUS](https://opus.nlpl.eu/Tatoeba/) | CC BY 2.0 FR |

Примеры употребления — это живые фразы носителей с готовым русским переводом, а не
сгенерированный текст. Корпус скачивается одним gzip-файлом и разбирается скриптом
`npm run db:examples`; сервер запускает тот же разбор фоном при старте, если в словаре
есть слова без примеров. Слова, которых в корпусе не нашлось, добираются генерацией
через OpenAI — по требованию и только при заданном `OPENAI_API_KEY`.

Переводы происходят из Викисловаря и распространяются по CC BY-SA 3.0 — при
использовании данных сохраняйте атрибуцию. Она показана в футере приложения и отдаётся
эндпоинтом `GET /api/health`.

## Команды

| Команда | Что делает |
| --- | --- |
| `npm run setup` | Установка зависимостей и подготовка базы со словарём |
| `npm run dev` | Backend и frontend в режиме разработки |
| `npm run build` | Сборка обоих пакетов |
| `npm start` | Продакшен-режим: API отдаёт и собранный фронтенд |
| `npm run typecheck` | Проверка типов в backend и frontend |
| `npm run db:studio` | Prisma Studio для просмотра базы |
| `npm run db:import` | Повторный импорт словаря (существующие слова обновляются) |
| `npm run db:examples` | Подбор примеров употребления из корпуса Tatoeba |
| `npm run db:reset` | Пересоздать базу с нуля и заново импортировать словарь |

## Переменные окружения

Файл `backend/.env`, шаблон — `.env.example`.

| Переменная | Назначение |
| --- | --- |
| `DATABASE_URL` | Путь к файлу SQLite относительно папки `backend` |
| `PORT`, `HOST` | Адрес API |
| `JWT_SECRET` | Секрет для подписи токенов, обязательно свой |
| `CORS_ORIGIN` | Разрешённые источники через запятую |
| `OPENAI_API_KEY` | Ключ OpenAI; без него разделы ИИ выключены |
| `OPENAI_MODEL` | Модель, по умолчанию `gpt-4o-mini` |
| `OPENAI_BASE_URL` | Необязательный свой базовый URL (прокси, Azure, OpenRouter) |

## Развёртывание

Локально:

```bash
npm run build
npm start          # Fastify отдаёт API и собранный фронтенд с одного порта
```

База — файл SQLite; для резервной копии скопируйте `backend/prisma/dev.db`.

### CI/CD на VPS

Пуш в ветку `release-server` гоняет проверку типов и сборку, затем по SSH
обновляет сервер: `git pull`, `npm ci`, Prisma, сборка, `systemctl restart lexio`.
Словарь заново не импортируется, `.env` и база на сервере не перезаписываются.
Перед обновлением схемы копируется `backend/prisma/dev.db` в `backend/prisma/backups/`.

**1. Секреты в GitHub** → Settings → Secrets and variables → Actions:

| Секрет | Что положить |
| --- | --- |
| `SSH_HOST` | IP или домен VPS |
| `SSH_USER` | пользователь деплоя, например `lexio` |
| `SSH_PRIVATE_KEY` | целиком приватный ключ (`-----BEGIN OPENSSH PRIVATE KEY-----` …) |
| `SSH_PORT` | необязательно, по умолчанию `22` |
| `DEPLOY_PATH` | необязательно, по умолчанию `/opt/lexio` |

Ключ лучше отдельный, не ваш личный. На сервере публичная часть — в
`~lexio/.ssh/authorized_keys`.

**2. Первый раз на Ubuntu 22.04/24.04** (от root):

```bash
git clone https://github.com/two-lifes/english-teacher.git /opt/lexio
cd /opt/lexio
sudo bash scripts/server-setup.sh
# отредактируйте /opt/lexio/backend/.env (JWT_SECRET, CORS_ORIGIN, OPENAI_API_KEY)
# если setup остановился на .env — повторите:
sudo bash scripts/server-setup.sh
sudo usermod -s /bin/bash lexio
```

Пользователю `lexio` нужен bash, чтобы GitHub Actions мог зайти по SSH.
Сервис слушает порт 4000; снаружи удобнее nginx (`deploy/nginx.example.conf`) и
Let's Encrypt.

**3. Ветка деплоя.** Когда секреты и сервис на месте:

```bash
git checkout -b release-server
git push -u origin release-server
```

Дальше: мержите в `release-server` (или пушите туда) — уйдёт выкладка.
Вручную: Actions → Deploy → Run workflow.

**Если Deploy падает с «Сервис lexio ещё не установлен»** — на VPS один раз от root:

```bash
cd /opt/lexio
git pull origin release-server
sudo bash scripts/install-service.sh
```

Затем перезапустите workflow в GitHub Actions.

При переезде на PostgreSQL меняется `provider` в `prisma/schema.prisma` и адаптер
в `src/db.ts`; поля, где SQLite вынуждал хранить списки строками JSON, можно
перевести в нативные массивы.
